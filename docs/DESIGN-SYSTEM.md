# Designer operating map

SKILL.md is the orchestration source of truth. references/capabilities.md routes
lazy knowledge loading. Do not maintain a second conflicting pipeline here.

| Layer | Package / evidence |
|---|---|
| Tier 0–4 routing / existing-system discovery | SKILL.md |
| Product/UX model | Selected licensed UX stage + context/research assumptions |
| Aesthetic influence | data/frontend-design.md |
| References | 192 product types + 74 brands + 67 archetypes; contextual fit/gaps |
| Direction / grammar / lock | references/design-director.md, design-grammar.md, DESIGN.md-template.md |
| Component reuse | Existing project → Storybook → applicable registry → primitives → justified custom |
| Browser | Shared pinned runtime or actually connected client MCP |
| Critique | references/design-review.md; deepest true defect classification |
| Flow | Outcome assertions and realistic error paths, not DOM existence |
| Preferences | External state; no example-as-personal-preference inference |

Full optional enrichment is pinned and installable without a private home collection.
Package-relative paths are used throughout active instructions. Personal evals and
receipts are not shipped; migrate legacy evals explicitly and non-destructively.

Definition of done requires actual rendered review/flow evidence at the task's tier.
Readiness is graded. Source presence, entry placement, client discovery, browser
launch and MCP operation are independent claims.
