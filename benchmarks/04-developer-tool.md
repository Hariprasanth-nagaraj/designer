# Benchmark 4 — Developer tool

**Fixed brief.**

Design the main screen of a deployment/observability tool for backend engineers who
live in it during an incident and glance at it the rest of the time.

Must support: see service health; find the failing request; read its logs and traces;
roll back; and read a post-incident summary.

## Why this brief
Tests code-forward visual character, terminal-adjacent typography, information density
without noise, and restraint. Also the domain with the strongest reference coverage
(raycast, vercel, warp, github) — a fair place to check reference selection is doing
work rather than defaulting to a fashionable pick.

## Rubric
| Dimension | What to look for |
|---|---|
| Product reasoning | Does it know an incident is read under time pressure? |
| IA | Logs/traces/deploys — are these one object or three screens? |
| Colour | Semantic severity used sparingly and correctly? |
| Typography | Mono used with intent, not everywhere? |
| Density | Operations density, consistent? |
| Components | No card wall; log stream treated as data? |
| Craft | Does it look like a tool engineers trust, or like a landing page? |
| Flow | Alert → failing service → request → logs → rollback → summary reflects it? |
